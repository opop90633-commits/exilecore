# 星骸輔助模組（exilecore_client）

星骸伺服器的**選用**客戶端模組（Fabric）。不裝也能正常玩；裝了多這些：

- **技能鍵**：10 個可以自己綁的按鍵（控制 → 按鍵綁定 → 分類「星骸」），對應伺服器的 10 個技能格
  （左鍵格、右鍵格、潛行＋左鍵格、潛行＋右鍵格、數字鍵第 1～6 格）。按下去跟按滑鼠、數字鍵放技能完全一樣，
  按住也一樣（連發、蓄力、持續引導）。預設都沒綁，請綁在原版沒用到的鍵上（例如 R、G、Z、V），
  綁在原版也在用的鍵上會兩邊都觸發。
- **技能列**：技能圖示、冷卻（暗色從上往下退＋秒數）、可以存好幾次的技能剩幾次、放不了的時候（魔力不足、武器不符、營地）變暗紅。
- **增益列**：增益名稱、剩下的時間與比例。
- **目標框**：準心指著（20 格內）或最後打到的怪物：名稱（照稀有度上色）、等級、生命條、護盾 %、身上的異常／詛咒／印記／曝露。
- **生命球、魔力球**（1.2.0 起）：快捷欄左邊一顆紅色生命球、右邊一顆藍色魔力球（PoE 風格），液面照比例平滑地動、有波紋，
  剛被打掉的那段淡淡的留一下；保留的生命（魔力）是球頂的灰色；球上寫目前／最大。
  1.3.0 改成 PoE 1 的樣子：能量護盾是疊在紅色生命上面一層半透明的藍白色液面（高度照能量護盾比例；1.2 是外環）；混沌免疫（最大生命 1）
  生命球整顆是能量護盾；心靈昇華（受到的傷害先扣魔力）在魔力球的框上畫一段紫紅色（長度照比例）、框下緣寫比例，生命球框上點一個紫紅色的小點。
  原版的愛心、飢餓條藏起來（盔甲、氧氣、坐騎血量照原位）。按 **F9** 切回原本的樣子（愛心位置的生命條，保留的生命是灰色、
  「受到的傷害先扣魔力」照比例畫藍色，上面一條能量護盾條）。
- **特效改由模組繪製**（1.1.0 起，見下面）：技能與地面範圍的特效由模組在你的電腦上畫，伺服器不用一顆一顆送粒子給你。
- **自動更新**（見下面）。

只有連上星骸伺服器（伺服器回了模組的招呼）時才有作用；連到別的伺服器、單人遊戲時什麼都不做，原版畫面照舊。

## 玩家安裝

1. 安裝 [Fabric Loader](https://fabricmc.net/use/installer/)（0.20.1 以上），版本選 **Minecraft 26.2**。
2. 下載 [Fabric API](https://modrinth.com/mod/fabric-api)（26.2 用的版本，例如 `0.161.0+26.2`）放進 `.minecraft/mods/`。
3. 把 `exilecore_client-版本.jar` 放進 `.minecraft/mods/`（伺服器網頁的 `/mod/manifest.json` 裡有下載網址，或跟管理員拿）。
4. 用 Fabric 的設定檔開遊戲、連上伺服器。

需要 Java 25（Minecraft 26.x 的啟動器已經內建）。

### 設定

- 按 **F7**（可以改，分類「星骸」裡的「開關星骸 HUD」）整個開關模組的 HUD；關掉時伺服器照沒裝模組的樣子顯示（動作列的增益倒數、藍色的吸收愛心）。
- 設定檔在 `.minecraft/config/exilecore_client.json`（關遊戲時改）：
  - `showSkillBar`、`showBuffs`、`showTarget`、`replaceHearts`、`showKeyLabels`：各部分開關
  - 1.4：`showNotices`、`showPanels`、`showResources`、`showStatus`、`showXp`、`showSides`、`panelsCollapsed`、`collapsedPanels`、`panelsX/Y`（見下面「畫面配置」）
  - `orbs`：生命、魔力畫成球（預設 true；false = 原本的生命條；遊戲裡按 F9 也會改這個）
  - `drawEffects`：特效改由模組繪製（預設 true；遊戲裡按 F8 也會改這個）
  - `scale`：縮放（0.5～3）
  - `skillBarX/Y`（畫面下方正中間為準）、`buffsX/Y`（畫面下方正中間為準，往左長）、`targetX/Y`（畫面上方正中間為準）：位置，單位是 GUI 像素
  - `autoUpdate`：自動更新（false = 只提示有新版）
  - `manifestUrl`：自己指定更新說明檔的網址（空白 = 用伺服器給的）

## 生命球、魔力球（1.2.0、1.3.0）

位置跟資源包版（沒裝模組的人看到的）一樣：

- 貼著快捷欄兩側，在副手格與攻擊冷卻指示的外側（主手換到左邊時副手格在右邊、攻擊冷卻指示在左邊，也都在球的內側，球不用動）；
  不放在畫面角落（左下是聊天、右下是字幕）。
- 球高 38 格（`scale` 小於 1 時跟著縮小，再大也不超過 38），不會壓到聊天欄最下面那行（畫面底往上 40 格）。
- 1.3：有球時技能列放在快捷欄正上方（經驗等級數字的上面，按鍵寫在格子左上角；1.2 是推到右球外側，會疊到右下角的字幕），
  盔甲、氧氣泡泡往上移 15 格、坐騎血量往上移 25 格（技能列上面、動作列下面）；增益列在左球外側、聊天欄最下面那行的下面排兩排，
  一欄兩個往左排，放不下的寫「+N」。沒有球（F9）照原本的位置。
- 原版的愛心、飢餓條藏起來。
- 1.3：有球時動作列不寫生命、能量護盾、魔力的數字與「Lv.31 42.0%」（守護、異常、提示照舊），原版經驗條改顯示角色經驗
  （等級數字＝角色等級、條＝到下一級的百分比）；沒有球時經驗條照舊顯示魔力。這些是伺服器照模組的招呼做的。

伺服器那邊：模組畫生命時（`replaceHearts` 開著、F7 沒關）伺服器不送資源包版的球、也不用吸收愛心；按 F7 關掉模組 HUD 時改看資源包版的球。
資料用的是原本 `exilecore:hud` 的 `vit`（生命、最大生命、保留、能量護盾、最大能量護盾、魔力、最大魔力、傷害先扣魔力的比例）；
1.3 起插件多送 `rmp`（保留的魔力，0 不寫），模組的招呼多寫 `"orbs":true`（有球時）。都只是多欄位、協定不升：
舊模組配新插件（沒寫 orbs = 照舊顯示）、新模組配舊插件（舊插件不認得 orbs，動作列、經驗條照舊，只是數字會跟球重複）都照常。

## 特效改由模組繪製（1.1.0）

裝了 1.1.0 以上的模組、而且這個功能開著時，伺服器不再把技能特效、地面範圍的粒子一顆一顆送給你，改送「哪裡有什麼特效」的簡短描述，
由模組在你的電腦上畫。網路比較省、人多的時候比較不卡；沒裝模組（或裝 1.0.0）的人照舊收伺服器的粒子，看起來跟以前一樣。

- **一次性的特效**（打中的火花、爆開的一團、一圈、線）：模組用遊戲本身的粒子畫，顏色、顆數、散開的範圍跟伺服器送的一樣，
  照你的「特效等級」與「別人的技能特效」設定打薄（跟以前一樣）。
- **持續的範圍**（燃燒地面、毒雲、聖化地面、裂隙、光環……）：地上畫一圈**細的彩色線**（跟著地形高低走），
  範圍型的裡面是**半透明**的一片，顏色照特效（火焰橘、靈魂火青、塵粒照原本的顏色……），再加上少量粒子；比以前一圈一圈的點更清楚、不擋視線。
  - **重要的**（Boss／怪物招式的預警、地圖機制的危險區）：顏色偏紅、外框**一秒閃一次**（變粗變亮），一眼就看得出要躲。
  - 範圍結束（或伺服器說消失）就不畫；萬一沒收到結束的訊息，時間到了也會自己消失。
- 遊戲的 **選項 → 視訊設定 → 粒子**：「全部」照常、「減少」範圍裡撒的粒子少一半、「最少」不撒粒子（地上的圈照畫；一次性的粒子照遊戲本身的規則減量）。
- 換世界（進地圖、回城）、斷線時全部清掉。

**開關**：按 **F8**（可以改，分類「星骸」裡的「開關「特效改由模組繪製」」），或設定檔的 `drawEffects`（true／false）。
關掉時模組會重新跟伺服器打招呼，伺服器改回送粒子（已經在畫的範圍畫到結束為止）。伺服器沒開這個功能時會提示，照舊用伺服器的粒子。

跟以前用粒子畫的差別：

- 持續範圍的外框是一條連續的線（以前是一顆一顆的點），裡面是半透明的一片，粒子比以前少；線不受光線影響（晚上、洞穴裡也一樣亮）。
- 地上的線照你那邊已經載入的方塊量高度（每 2 秒重量一次），所以樓梯、半磚上會貼著表面；懸空或還沒載入的地方用伺服器給的高度。
- 一次性的粒子用你這邊的亂數散開，所以每個人看到的位置不會一模一樣（以前也只是隨機）。

## 自動更新怎麼運作

1. 開遊戲時（用上次記下的網址）、以及進伺服器時伺服器說有新版時，模組讀伺服器的 `/mod/manifest.json`（`{version, url, sha256, changelog}`）。
2. 比現在的新，就下載到 `mods/exilecore_client-新版本.jar.pending`，算 SHA-256，**跟說明檔對不上就刪掉、不用**。
   下載好會跳通知：「新版本已下載，重開遊戲後生效」。`.pending` 不是 `.jar`，Fabric 不會載入它。
3. **關遊戲時**換檔：刪掉舊的 jar、把 `.pending` 改名成 `exilecore_client-新版本.jar`（Fabric 不准同一個模組有兩個 jar，舊的一定要先刪）。
   - Windows：遊戲開著時 jar 被鎖住，所以另外跑一個小批次檔（`config/exilecore_client-update.cmd`），每秒試一次、最多等 60 秒，換好後刪掉自己。
   - macOS／Linux：直接換（開著的檔案也刪得掉）；換不了才用 `sh` 在背景等 2 秒再換。
4. 下次開遊戲時清掉剩下的（已經換上的 `.pending`、下載到一半的 `.part`、批次檔）。上次沒換成功的新版會再驗證一次雜湊，這次關遊戲時再換。

下載的檔案除了「下次開遊戲時被 Fabric 當成模組載入」之外不會被執行。從開發環境（不是 mods 裡的 jar）跑的時候不會自動更新。

## 管理員

- 把新的 jar 丟進伺服器的 `plugins/ExileCore/clientmod/`（舊的可以留著，用版本最新的那個）。版本照 jar 裡的 `fabric.mod.json`，
  SHA-256 照檔案內容自動算，不用改設定；10 秒內生效。
- 網址：`<web.public-url>/mod/manifest.json` 與 `<web.public-url>/mod/<檔名>.jar`（內建網頁伺服器）。
- `config.yml`（都可以不寫，下面是預設值）：

  ```yaml
  client-mod:
    enabled: true        # false = 不理模組的封包（裝了模組的人也照沒裝的顯示）
    hud-interval: 3      # 畫面資料最快幾 tick 送一次（2～20；沒變就不送）
    public-url: ""       # 更新說明檔用的網址；空白 = 用 web.public-url
    changelog: ""        # 更新說明檔裡的更新說明
    effects: true        # false = 不讓模組畫特效（裝了 1.1 的人也照常收粒子）
    fx-max-bytes: 16384  # 特效封包每人每 tick 最多幾位元組（1024～262144）；超過的那些改送粒子，
                         # 重要的（預警）可以用到 4 倍，再超過也是改送粒子，不會不見
  ```

- 協定：模組 1.1 打招呼時送 `protocol: 2` 與 `effects`；伺服器回兩邊都會的最高版（1.0 的模組送 1、收到 1，照舊運作）。
  特效封包 `exilecore:fx` 一個人一個 tick 最多一包（tick 結束時送），格式在插件的 `tw.exilecore.clientmod.FxProtocol`
  與模組的 `tw.exilecore.client.core.FxCodec`。

## 開發者：自己編

```sh
cd client-mod
sh ./gradlew build     # 需要 JDK 25；產出 build/libs/ 與 dist/exilecore_client-<版本>.jar
```

版本在 `gradle.properties` 的 `mod_version`。Minecraft 26.2、Fabric Loader 0.20.1、Fabric API 0.161.0+26.2、Fabric Loom 1.19.3、Gradle 9.8.2
（Minecraft 26.x 沒有混淆，不用 Yarn 對應表）。封包格式寫在 `src/main/java/tw/exilecore/client/core/Protocol.java`
與插件的 `tw.exilecore.clientmod.ClientModProtocol`，兩邊要一起改；特效封包是 `core/FxCodec.java` 與插件的
`tw.exilecore.clientmod.FxProtocol`（`FxCodecTest` 裡有插件實際產生的一包，用來確認兩邊對得上）。
